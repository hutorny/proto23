# Changelog

All notable changes between tags `rev.2` and `rev.5`, newest first.
Changes are derived from the git history (`git log rev.1..rev.5`).

## rev.5 — 2026-11-13

### Added
- `enum_traits<E>::name(value)` and `enum_traits<E>::label(value)` for generated enums.
  `name()` returns the protobuf value name; `label()` returns a human-readable label.
  Both return an empty `std::string_view` for unknown values.
- Enum value label sources, in order of precedence:
  1. a custom `string` option with field number `68227` on `google.protobuf.EnumValueOptions`;
  2. the value name with the enum prefix stripped (the prefix is whatever precedes `UNSPECIFIED` /
     `unspecified` / `Unspecified` in the zero value, e.g. `COLOR_UNSPECIFIED` → prefix `COLOR_`);
  3. the plain value name.
- The plugin emits a new `<name>.proto23.hpp` file beside `<name>.proto23.h`, holding the out-of-line
  `name()` / `label()` implementations. Include it where those functions are needed.
- Compile round-trip tests and plugin tests for enum `label()` / `name()`.

### Changed
- Empty messages are now recognised by the `proto23::empty_message` concept (a message whose `Fields<>`
  has no fields) instead of `std::is_empty_v`. `Fields<>` no longer requires at least one field, and the
  plugin emits `using Model = proto23::Fields<>;` for messages without fields.
- Plugin descriptor: `FieldOptions::packed` is now `std::optional<bool>`, so `packed_t::yes` / `packed_t::no`
  is emitted only when `[packed=...]` is set explicitly.

### Fixed
- `optional<std::string>` deserialization (the `optional` / `unique_ptr` wrapper overloads are now declared
  after the `string` overload).
- In-place `repeated` message fields were wrongly tagged with the `packed` attribute.
- Byte-array reads now use the clamped element count rather than the wire length, avoiding over-read
  when the input exceeds the container capacity.
- Concepts evaluated differently by clang and gcc (`elementary`, `string_like`); `std::byte` is no longer
  treated as a user enumeration.
- Packed arrays of contiguous scalars are serialized directly, without an intermediate buffer.

## rev.4 — 2026-09-13

### Added
- `proto23/enum_traits.h`: `enum_traits<E>` with `min()`, `max()`, `count()`, `mask()` and `is_sequence`,
  generated by the plugin for every enum.
- The plugin translates the protobuf `deprecated` option into `[[deprecated]]` for message fields, enums
  and enum values. It is suppressed for protobuf core files.
- Test masters and tests for message ID, options and deprecated handling.

### Fixed
- Issue #3: an empty but present nested message caused the next field to be misread.
- Issue #5: the plugin assumed the message ID type belonged to the file's package. It now emits the enum's
  fully-qualified type name and the static member name from the option definition.

## rev.3 — 2026-06-13

### Added
- `proto23/diagnostic.h`: `proto23::diagnostic::explain` turns `parse_error` flags into readable messages.
- C++ CI workflow building with multiple compilers (GCC 13/14, Clang 18/19/20).
- README: "Tested with" matrix.

### Changed
- External messages (message types defined outside generated code) are assumed complete and may be
  generated in-place.

### Fixed
- Deserialization gives up early when `tellg()` returns `-1` (reported as `parse_error::tellg_fail`).

## rev.2 — 2026-06-07

### Added
- Support for empty messages.
- In-place fields support in the plugin (`inplace_string`, `inplace_vector`, in-place messages).
- Plugin tests (`make plugin-test`).

### Fixed
- Code generation with the plugin.
- `<spanstream>` include caused errors with clang.
